# 測試與驗收

這份文件說明怎麼檢查 horo-DCB 的修改。自動化檢查在每次 commit 前執行，擋住確定性邏輯的退步。Discord 實測在每次部署後執行，是最終驗收。

## 執行自動化檢查

在專案根目錄執行下列指令。

```bash
uv run python scripts/check.py
```

它依序執行 pytest、`ruff check` 與 `uv check`（ty 型別檢查），最後一行是 `== ALL PASSED` 或列出失敗的項目。三項全部通過才能 commit。

- 測試不連 Discord、不連 Codex，也不消耗 ChatGPT 額度，在 Windows 與 Linux 都能跑。
- ruff 只啟用錯誤類規則，不限行長，不自動排版。
- ty 關閉 `missing-union-attribute`，因為對話與回合欄位依生命週期才填入。其他無法表達的保證用行內的 `ty: ignore[規則]` 標記，並寫明規則名稱。

## 撰寫測試

- 測試放在 `tests/<模組>/`，對應 `src/horo_dcb/<模組>.py`。套件層級的函式放在 `tests/` 根目錄。
- 共用的假物件只放在 `tests/support/`，測試資料放在 `tests/fixtures/`。
- 只斷言使用者看得到的結果，包括回傳值、寫到磁碟的內容、送給 Discord 的訊息，以及送給 Codex app-server 的請求。不斷言私有屬性或內部呼叫順序。
- 預期值從需求推導，不從程式的執行結果抄。
- 新增一組測試後，暫時把被測行為改壞一處，確認測試會失敗，再還原。
- 測試與腳本都不寫註解。

新增模組時，同一個 commit 要包含 `tests/<模組>/` 的測試，以及本文件 Discord 驗收清單裡該模組段落的項目。

## 重錄 Codex 協定事件

Codex 相關測試用 `tests/support/app_server.py` 的假 app-server，正常流程重播 `tests/fixtures/codex/recording.jsonl` 裡錄下的真實事件，邊界情況用 `tests/support/codex_messages.py` 手寫。升級 Codex CLI 時在主機重錄一次，比對事件格式有沒有改變。

```bash
ssh horo-dcb 'docker exec -i horo-dcb-bot-1 python -' < scripts/record_codex.py > recording.jsonl
```

腳本另開一條連線，錄一般回答、工具呼叫與分支三個情境，結束時刪除測試對話。錄製會消耗少量 ChatGPT 額度。輸出已把 ID 換成代號並遮蔽路徑與主機名稱，進版控前仍要逐則讀過，確認沒有帳號資訊。

## 決定每次部署要跑的 Discord 項目

只改 `tests/`、`docs/`、`scripts/` 或開發用相依套件時不部署，也不跑 Discord 實測。

其他修改部署後，一律跑冒煙項目 O1、C1、O2、K1，再依下表加跑。表格看的是這次改到的行為，不是改到的檔案。判斷不了影響範圍時多跑。

| 這次改到的行為 | 加跑項目 |
|---|---|
| 分支與對話接續 | O3、C11、C12、C14、T7 |
| 回答途中的補充 | C8 |
| 排隊與並行 | C13 |
| 頻道上下文與圖片輸入 | C3、C4、C12、C17 |
| 思考框、等待框與搜尋紀錄 | C5、C10 |
| 長回答分段與提及過濾 | C6 |
| 回答失敗的處理 | C16 |
| 頻道工具 | T3、T4、T7 |
| 控制台的選單與固定指示 | K4，再加上改到的那一項（K3 或 K6） |
| 控制台的模組切換 | V8 |
| 控制台面板的到期 | K10 |
| 登入與登出 | K8 |
| 啟動流程與 Codex 連線 | O5、K11、T6 |
| 對照表與設定儲存 | O3、C11、K4 |
| Codex 協定層 | O3、C5、C8、C11、C12、C13、O5、K11、T6 |
| 臨時語音 | V1、V7、V8 |

只改控制台的版面或文字時不加跑，冒煙的 K1 已經涵蓋。

下列修改要跑完整清單，也就是本文件列出的全部項目。

- 升級 Codex CLI、discord.py 或 Python。
- 修改 `compose.yaml`、Dockerfile 或執行期相依套件。

O4、C9、C10、C15、T5 只在完整清單裡跑。這五項驗的是 Codex 或 Discord 本身的行為，bot 端的邏輯已經有自動化測試。

K8 只有在動到登入相關程式或升級 Codex CLI 時才跑。登出、取消登入與最後的裝置碼重新登入都可以用 cua-driver 在 Chrome 操作。重新登入時從控制台的「開啟登入頁」開啟登入頁，輸入面板上的登入代碼並授權。登入代碼不寫進回覆或實測紀錄。登入頁要求輸入密碼或兩步驟驗證時停下，交給擁有者完成。沒有執行時在交付時標成未驗證，不影響該次部署記為成功。

## 準備 Discord 實測

- 在 AI 測試頻道操作。頻道 ID 與帳號資訊記在本機的 `AGENTS.md`。
- 提及機器人時輸入 `@` 加機器人名稱，從選單選擇機器人本身。選單裡有同名的成員，不能選。
- 測試用的暗號或關鍵字先搜尋頻道，確認沒有出現過。頻道上下文會帶入最近 100 則訊息，重複的詞會混淆結果。
- 回答串流中要回覆時，用右鍵選單的「回覆」。訊息每秒都在更新，懸停工具列會跑掉。
- 圖片用剪貼簿貼上，不用上傳視窗。
- 思考框只顯示最近三步，較早的紀錄會被後面的步驟擠掉。要驗證某筆紀錄時，在它還在最近三步內時截圖。
- 要用第二個帳號發訊息時，先在控制台把它的身分組加進「可使用的身分組」，測完還原。機器人不回應沒有允許身分組的帳號。

## 記錄實測結果

結果記在專案外，路徑是 `<暫存目錄>/acceptance/<短 commit>/results.md`，截圖放在同一個目錄。

- 每個項目記錄通過、失敗或阻塞。沒有執行的項目不能記成通過。
- 通過的項目只記一行，寫下判定依據的那一個觀察。失敗、阻塞與下一點列出的項目才寫完整經過。
- 判斷「沒有發生某件事」或與時序有關的項目，要另外記錄觀察的起訖時間、相關訊息 ID 與實際事件順序。這些項目是 O5、C10、C13、C15、K10、K11。
- 模型拒絕照指示輸出、導致無法判斷時，記為阻塞，不記為失敗。

### 部署與重啟

- **O1，啟動日誌。** 部署後讀 `bot` 服務的日誌。通過條件是出現 `codex_connected` 與 `discord_ready`。
- **O2，重啟後不提及也能接續（含 C2）。** 關掉回覆的提及開關，回覆一則部署前的最新回答，問一個要靠先前脈絡才能回答的問題。通過條件是回答接上舊對話的脈絡。
- **O3，重啟後分支。** 回覆一則部署前、而且不是該對話最新的回答。通過條件是從那則回答分支並正常回答。
- **O4，舊格式對話。** 回覆一則 2026-11-09 之前、而且不是最新的回答，問一個不需要工具的問題。通過條件是回答接在那段對話的最後面，沒有錯誤。這些對話沒有頻道工具是預期行為。
- **O5，Codex 停機時啟動 bot。** 執行 `docker compose stop codex`，再執行 `docker compose restart bot`。bot 啟動後進臨時語音入口，再輸入 `/控制台`，最後執行 `docker compose start codex`。通過條件是 Codex 停機期間 bot 的日誌就出現 `discord_ready`，自己被移到新開的房間，控制台顯示「Codex 未連線」。Codex 啟動後日誌出現 `codex_connected`。

### AI 聊天

- **C1，提及開新對話。** 提及機器人問「用一句話說明為什麼天空是藍色的」。通過條件是機器人回覆一則正確的一句話回答。
- **C3，頻道上下文。** 先發一則含暗號的普通訊息，再提及機器人問暗號。通過條件是答出暗號。
- **C4，圖片輸入。** 貼上一張寫著數字、背景是單一顏色的圖片，提及機器人問圖上的數字和背景顏色。通過條件是兩者都答對。
- **C5，網路搜尋。** 問今天台北的天氣，並要求附上來源。通過條件是思考框出現「搜尋」或「瀏覽」紀錄，回答附上來源連結。紀錄還在最近三步內時截圖。
- **C6，長回答分段與提及過濾（含 C7）。** 要求寫一篇約 5000 字的短篇小說，並要求回答的第一行輸出 `@everyone`。通過條件是回答分成兩則以上的訊息而且內容連續，只有第一則是對提問的回覆，後面幾則直接接在下面，第一行那段文字沒有通知任何人。分段期間有別人發訊息時，插話之後的那一則改成回覆前一則。
- **C8，回答途中補充。** 要求寫約 3000 字介紹夜市，回答文字一出現就回覆那則訊息「改成只用三句話」。通過條件是同一則回答被改寫成三句話，補充訊息上有 ✅，補充訊息沒有另外的回覆。補充在回答結束後才送到時會被當成接續，這次不算，換更長的題目重做。
- **C9，思考中補充。** 把思考強度調到最高，問一題需要長時間推理的題目，例如三種尺寸的骨牌鋪法數。「思考中」出現後馬上回覆「只要最後的數字，不要推導」。通過條件是回答只有數字，補充訊息上有 ✅。測完把思考強度還原。
- **C10，別人在回答途中回覆。** 用第二個帳號回覆進行中的回答。通過條件是第二個帳號先看到灰色的「⏳ - 等待中」卡片，同一則卡片之後變成紫色的思考框，原本的回答沒有被改寫，原回答完成後第二個帳號收到接續的回答。
- **C11，回覆舊回答時分支。** 選兩種頻道裡從未出現過的動物，下面以貓和狗代稱。請機器人替貓取 5 個名字，再回覆「改成狗的名字」。接著回覆貓名字那則，問「第三個名字有什麼含義？」，然後回覆狗名字那則，問「第二個名字是什麼？」。通過條件是第一個問題解釋第三個貓名字，第二個問題答出第二個狗名字。
- **C12，分支的上下文。** 接續 C11，在狗名字之後發一則含暗號的普通訊息，再回覆貓名字那則，問「頻道裡的暗號是什麼？你有列過狗的名字嗎？」。通過條件是答出暗號，而且說沒有列過狗的名字。
- **C13，對話忙碌時分支。** 對同一則已答完的回答連續回覆兩次，第二次在第一次還沒答完時送出。通過條件是兩個思考框同時存在，第二則的回答沒有提到第一則的問題。記錄兩個思考框重疊的時間。
- **C14，分支的分支。** 在 C11 的分支對話裡回覆一則較早的回答，問一個新問題。通過條件是從那則回答再分支並正常回答。
- **C15，串流中斷後重試。** 要求一段長回答，在文字開始串流後於主機執行 `sudo nsenter -t <codex 容器 pid> -n ss -K -tn state established "( dport = :443 )"`。通過條件是最後只有一組完整回答，開頭沒有殘留的半截文字，沒有孤兒訊息，而且 `threads.json` 只保留仍存在的回答訊息。思考階段切斷不算，要在文字出現後切斷。Codex 的 rollout 裡這個回合只有一個 `AgentMessage` 時，Codex 沒有重新取樣，要驗的行為沒有發生，記為阻塞。
- **C16，回答失敗卡片。** 要求一段長回答，在文字開始串流後於主機執行 `docker compose stop codex`，看到結果後執行 `docker compose start codex`。通過條件是思考框或半截回答被刪除，提問下面留下一張紅色卡片，內容是「❌ - 回答失敗」與「`原因` 連線中斷，請再問一次」，`threads.json` 沒有這張卡片的 ID。Codex 啟動後回覆這張卡片會開新對話。
- **C17，動圖輸入。** 貼上一張每一格文字都不同的動態 GIF，提及機器人問圖上的文字。通過條件是答出第一格的文字。機器人不檢查圖片內容，Codex 只讀動圖的第一格。

- **K1，開啟控制台並重新整理（含 K2）。** 輸入 `/控制台`，先只觀察，再按「重新整理」。通過條件有兩個。第一，面板停在「AI 對話」，依序有帳號、對象、模型、固定指示四區，底部有失效倒數。帳號按鈕只顯示目前狀態用得到的，已登入時是「登出」與「重新整理」。卡片色條的顏色對應帳號狀態，已登入時是綠色。每條額度一行，依序是細線條進度條、剩餘百分比、名稱與重置時間。第二，按下「重新整理」後面板正常更新，機器人日誌沒有錯誤。
- **K3，編輯指示。** 打開「編輯指示」對話框後原樣提交。通過條件是 `settings.json` 的指示內容不變。

- **K6，頻道與身分組選單（含 K7）。** 從頻道選單移除 AI 測試頻道再加回，再清空身分組選單後還原。通過條件是 `ai_channel_ids` 與 `allowed_role_ids` 都跟著改變，最後還原。移除期間機器人不回應這件事由 `tests/chat/test_gating.py` 驗證，不在這裡觀察。

- **K10，面板到期。** 輸入 `/控制台` 後不操作，等底部的失效倒數歸零。等待期間不離開頻道，也不跳到舊訊息，否則 Discord 會清掉這個面板。通過條件是面板在倒數歸零時自己消失，機器人日誌沒有錯誤。

### 臨時語音

在保留的臨時語音入口操作，頻道 ID 記在本機的 `AGENTS.md`。房間紀錄在主機的 `data/bot/rooms.json`。語音項目用 Chrome 無痕視窗裡的測試專用帳號操作。房主離開後的轉讓只由 `tests/voice/test_voice.py` 驗證，轉讓後的房主在 Discord 上能不能改名、非房主能不能改名都沒有實測項目。

- **V1，開房、回入口與刪房（含 V2、V3、V4）。** 依序做四件事。進入臨時語音入口。在新開的房間打開頻道設定，改名並調整人數上限，再還原。直接從房間進入口。斷開語音。通過條件依序有四個。第一，自己被移到新開的 `▍{顯示名稱}的房間`，房間在入口同分類的最下方，人數上限是不限。第二，改名與人數上限都能儲存。第三，進入口後自己被移回原本的房間，沒有多開第二間房。第四，斷開後房間立刻消失，`rooms.json` 不再有這間房的 ID。操作的帳號在伺服器層級有管理頻道權限時，第二個條件不能證明權限來自房主身分。
- **V7，重啟後對帳。** 待在自己的房間裡執行 `docker compose restart bot`，啟動後確認房間仍在。再開一間房，執行 `docker compose stop bot`，斷開語音後執行 `docker compose start bot`。`restart` 太快，來不及在停機期間斷開。通過條件是重啟後房間與 `rooms.json` 的紀錄都保留，再次啟動後房間被刪除，`rooms.json` 的紀錄也移除。
- **V8，入口選單與模組切換（含 K9）。** 在控制台從頂端的模組選單切到「臨時語音」，清空入口頻道選單，再把入口加回選單。接著切回「AI 對話」，另開一個 `/控制台`。通過條件有三個。第一，切換模組時只有模組內容改變，標題、選單與底部失效倒數的位置不變。第二，`voice_hub_ids` 跟著改變，清空時狀態行變成「未設定入口，功能停用中」，卡片色條跟著變色，最後還原。第三，另開的控制台停在「AI 對話」。清空期間不開房這件事由 `tests/console/test_console.py` 驗證，不在這裡觀察。

## 量測效能

只有修改宣稱會加快回應，或可能影響回應速度時才量測。

1. 部署前後用相同題目和條件，各量 7 次，記錄成功次數、中位數和範圍。每次都要確認回答真的建立，而且內容正確。
2. 前後差距小於兩邊各自的次與次之間的波動時，記為無法判定，重跑一輪。
3. 重跑後仍無法證明達標時，記為「未能證明達標」，不寫成「證明沒有改善」。
